# django_first

Coursework/practice repository from 2018: a first exercise building a Django app — a bare-bones
"tienda" (store) with two models, `Producto` and `Categoria`, wired into the Django admin. There
are no custom views, templates, or URLs beyond `/admin/`; nothing is publicly reachable except
the admin panel. Treat it as a learning artifact, not a demo.

## What's in it

- `tienda/` — the Django project (`tienda/tienda/settings.py`, `urls.py`, `wsgi.py`).
- `tienda/productos/` — the one app, with `Producto` and `Categoria` models and an admin
  registration. `views.py` is empty (just the Django boilerplate comment).
- `tienda/db.sqlite3` — a pre-existing SQLite database committed to the repo.
- No `requirements.txt`, no tests beyond the default empty `tests.py`.

Generated by `django-admin startproject` on **Django 2.0.6**, per the comment in `settings.py`.

## How to run

Verified by actually installing and running it, not assumed:

- **As pinned (Django 2.0.6) it does not run on a current Python.** `pip install Django==2.0.6`
  installs fine under Python 3.12, but `manage.py` fails immediately:
  `ModuleNotFoundError: No module named 'distutils'` — `distutils` was removed from the
  standard library in Python 3.12, and Django 2.0.x still imports it. This project predates
  that removal by several years.
- **It does run under a modern Django on Python 3.12.** Installing `Django==4.2.*` instead and
  running `python manage.py check` from `tienda/` succeeds, with two harmless warnings
  (`models.W042`, missing `default_auto_field` — cosmetic, not a bug in the code shown here).
  From there `python manage.py migrate` and `python manage.py runserver` are expected to work
  normally, though only the admin panel exists to visit.
- To run it today: use Python 3.10+ with `pip install "Django>=4.2,<5"` (or spin up Python
  3.6/3.7 with the original `Django==2.0.6` if you want the exact original stack), then from
  `tienda/`: `python manage.py migrate && python manage.py createsuperuser && python manage.py runserver`.

No live demo, no deployment — this was never intended to be published.

## Cómo correrlo

Verificado instalando y corriendo el proyecto de verdad, no asumido:

- **Tal como está fijado (Django 2.0.6) no corre en un Python actual.** `pip install
  Django==2.0.6` instala sin problema en Python 3.12, pero `manage.py` falla de inmediato:
  `ModuleNotFoundError: No module named 'distutils'` — `distutils` se eliminó de la librería
  estándar en Python 3.12, y Django 2.0.x todavía lo importa. Este proyecto es varios años
  anterior a esa eliminación.
- **Sí corre con un Django moderno sobre Python 3.12.** Instalando `Django==4.2.*` en su lugar
  y corriendo `python manage.py check` desde `tienda/`, funciona, con dos warnings inofensivos
  (`models.W042`, falta `default_auto_field` — cosmético, no un bug del código en sí). A partir
  de ahí `python manage.py migrate` y `python manage.py runserver` deberían funcionar con
  normalidad, aunque solo existe el panel de admin para visitar.
- Para correrlo hoy: usar Python 3.10+ con `pip install "Django>=4.2,<5"` (o levantar Python
  3.6/3.7 con el `Django==2.0.6` original si se quiere el stack exacto de la época), y desde
  `tienda/`: `python manage.py migrate && python manage.py createsuperuser && python manage.py runserver`.
